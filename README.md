# Bible Study — KJV Index & Summary Tool

An indexed, summarized version of the entire King James Version (KJV) Bible built locally with SQLite and a local LLM (Ollama). Fetches text from [bible-api.com](https://bible-api.com), generates chapter summaries via Ollama (`qwen3.6:35b-a3b-nvfp4`), stores everything in SQLite, and provides a lightweight browser to explore the results.

## Features

- **Full KJV corpus**: 66 books, ~1,189 chapters indexed automatically
- **AI-powered summaries**: Chapter-level & book-level summaries generated by local Ollama models
- **SQLite storage**: All verses and summaries stored locally for instant retrieval
- **YAML-configurable prompts**: Edit `config.yaml` to customise summary style without touching code
- **Browser viewer**: Lightweight HTTP server with clickable Bible navigation (auto-launches)
- **Markdown export**: Export every chapter's summary as linked markdown files
- **Tested codebase**: 100% test suite with 90%+ mutation testing target

## Quick Start

### Prerequisites

- **Python 3.14+** (managed via `uv`)
- **[uv](https://github.com/astral-sh/uv)** — fast Python package installer & resolver
- **[Ollama](https://ollama.com)** with model `qwen3.6:35b-a3b-nvfp4` running locally

### Installation

```bash
git clone <repo-url> && cd bible-study
uv sync
ollama pull qwen3.6:35b-a3b-nvfp4
```

## Usage

Download all 66 books and start generating summaries in three steps:

```bash
# Step 1: Download KJV text from bible-api.com into SQLite
uv run bible-study init

# Step 2: Generate chapter summaries via Ollama
uv run bible-study summarize

# (Optional) Step 3: Generate book-level aggregate summaries
uv run bible-study summarize-book

# Launch the browser viewer at http://localhost:8080
uv run bible-study view

# Check summarization progress
uv run bible-study status

# Export all summaries as markdown files to output/
uv run bible-study export
```

### Data directory

All commands accept `--data-dir DIR` (or `-d DIR`) to override the default `data/` location.

### What gets written to disk

`init` writes two things under `data/`, both persistent:

| Path | Contents |
|------|----------|
| `data/api-cache/<book>-<chapter>.json` | Raw API response, one file per chapter (~1,189 files) |
| `data/bible.db` | SQLite database — `verses`, `chapter_summaries`, `book_summaries` |

The JSON cache is checked before every request, so **re-running `init` costs
zero network calls** for chapters already downloaded. A full first run makes
~1,189 requests with a 0.5s pause between books.

Summaries live in the same database, so `summarize` is resumable — it only
processes chapters with no summary yet, and you can stop and restart it
freely. Per-chapter progress is appended to `data/SUMMARY_PROGRESS.md`.

To force a fresh download, delete `data/api-cache/`. To start completely
over, delete `data/`.

## CLI Reference

| Command | Description |
|---------|-------------|
| `bible-study init` | Download all KJV books to SQLite |
| `bible-study summarize` | Generate chapter summaries via Ollama (all unsummarized) |
| `bible-study summarize-book` | Generate book-level aggregate summaries |
| `bible-study view [--port PORT]` | Launch browser viewer on specified port |
| `bible-study status` | Show indexing/summarization progress |
| `bible-study export [-o DIR]` | Export summaries as linked markdown (default `output/`) |
| `bible-study config-edit` | Open config.yaml in default editor |

Every command also accepts `--data-dir DIR` / `-d DIR`.

## Customising Prompts

All prompts live in `config.yaml` at the repo root — **no code change is
needed**. `prompts.py` reads the file at runtime and substitutes `{...}`
placeholders by plain text replacement.

Two templates are used:

| Key | Used by | Placeholders |
|-----|---------|--------------|
| `chapter_summary` | `summarize` | `{book_name}`, `{chapter_number}`, `{chapter_text}` |
| `book_summary` | `summarize-book` | `{book_name}`, `{chapter_count}` |

Any placeholder you leave out is simply left alone; unknown keys are ignored.

### Where the config is found

`load_config()` resolves in this order, first match wins:

1. `$BIBLE_STUDY_CONFIG` — an explicit path, if set
2. `./config.yaml` — relative to the current working directory
3. `config.yaml` at the repo root

So you can keep experiment variants side by side:

```bash
BIBLE_STUDY_CONFIG=prompts/terse.yaml uv run bible-study summarize
```

### Seeing the prompt

To print the exact text sent to Ollama:

```bash
uv run python -c "
from bible_study.prompts import load_config, build_chapter_prompt
print(build_chapter_prompt(load_config(), 'Genesis', '<chapter text>', 1))
"
```

Prompts are also stored per chapter in the `chapter_summaries.prompt_used`
column, so you can audit exactly what produced any given summary.

### Re-running after a prompt change

`summarize` skips chapters that already have a summary. To regenerate with a
new prompt, clear the old ones first:

```bash
sqlite3 data/bible.db "DELETE FROM chapter_summaries;"   # all chapters
sqlite3 data/bible.db "DELETE FROM chapter_summaries WHERE book_name='Genesis';"
```

Verse text is untouched, so no re-download is needed.

### Changing the model

The model is set in `src/bible_study/ollama.py`:

```python
MODEL = 'qwen3.6:35b-a3b-nvfp4'
OLLAMA_BASE = 'http://localhost:11434'
```

## Architecture

```
cli.py (Click CLI)
    │
    ├── init         ─▶ api.download_all() ─▶ sqlite3 (db.py)
    ├── summarize    ─▶ summary.generate_all_chapters()
    │                    │                  ┌── ollama.generate() ── LLM
    │                    │                  └── db.save_summary()
    ├── summarize-book ─▶ summary.summarize_book()
    │                    │              ┌── ollama.generate()
    │                    │              └── db.save_book_summary()
    ├── view           ─▶ browser.serve()  (HTTP server on port 8080)
    ├── status         ─▶ db.get_chapter_progress() + indexer.total_chapters()
    └── config-edit    ─▶ opens config.yaml in default editor

summary.py ties together:
    - bible_study.db       (read verses, save summaries)
    - bible_study.api      (fetch fresh verse text when needed)
    - bible_study.ollama   (call local LLM for generation)
    - bible_study.prompts  (build YAML-configured prompts)
```

## Testing

All tests use pytest with mocks by default (no live API/LLM calls).

```bash
# Full test suite
uv run pytest

# With coverage report
uv run pytest --cov=bible_study --cov-report=term-missing

# With HTML coverage report in htmlcov/index.html
uv run pytest --cov=bible_study --cov-report=html

# Mutation testing (requires 90%+ unit coverage first)
uv run mutmut run

# Integration tests (live Ollama + bible-api.com; skipped by default)
uv run pytest --run-integration -m "integration"
```

## Architecture Decisions

- **SQLite** over a full database — zero external deps, single-file portable storage
- **bible-api.com** free tier for KJV text — no API key required
- **Local Ollama** for generation — data stays on-disk, offline-capable
- **Click CLI** for command orchestration — cross-platform, composable subcommands
- **YAML prompts** over inline strings — user-editable without code changes
- **Simple `.replace()` templating** instead of Jinja2 — no extra dependency
